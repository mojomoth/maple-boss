D1 + FN-1 (P1): no way to delete a saved party on /pocs/party
-----------------------------------------------------------
Root cause: the saved-party list is server-rendered and has no control at all. DELETE /api/party/[id] existed, but
only scripts called it.
Fix: each saved row ends in a "삭제" button (btn--quiet, 44px). Its accessible name is "#<id> <보스> 파티 삭제" (a
visually hidden prefix, so the name still contains the visible word). Pressing it calls DELETE /api/party/<id>.
  - 204, or 404 (already gone): router.refresh(). The row leaves the list, and the button reads "삭제 중…"
    (disabled, aria-busy) until then.
  - Other errors: the API's Korean { error }, or "파티를 삭제하지 못했어요 (<status>). 잠시 뒤 다시 시도해 주세요."
    when the answer is not JSON. If the server cannot be reached, it shows the shared offline text from
    messages.ts. The message goes in a role="alert" line under the row and the button comes back. A retry clears
    the line.

D2 (P1): the header boss field clipped 20 of 60 labels at 1440/1920
--------------------------------------------------------------------
Root cause, measured in Chrome: the text box was 15rem minus 12px left and 64px right padding. Inside that, Chrome
keeps about 20px for the type=search clear (x) glyph even while the glyph is hidden. The 44px icon button sits on
top of the padding, so the padding's last 20px were empty as well. Turning off the datalist indicator changed
nothing (it takes no room), so it stays.
Measured variants (60 labels; the number clipped at 1440, 1920, 1024 and 961):
  current 20 | padding 44px 8 | clear glyph off 12 | both 1 (카오스 가디언 엔젤 슬라임, 174.5px) | both + 16rem 0
Fix: .field-wrap .field { width: 16rem; padding-right: 44px } and ::-webkit-search-cancel-button { display: none }.
Esc still clears a search field, and the draft (maple-boss-main-dark-v2.png) shows only the magnifier in this field.
The field is 256px; the draft's is about 241px.

FN-2 (P1): after Back/Forward the boss field shows a different boss than the page; a dead history entry
--------------------------------------------------------------------------------------------------------
I found three causes:
 1. The field update was keyed on useSearchParams(). On Back/Forward Next commits the new URL one render before the
    page's props arrive. The effect therefore wrote the previous page's label and marked that URL as done. When the
    real props came, the effect skipped them, so the field stayed one step behind. With stale props it could also
    call history.replaceState with the old boss. In the pre-fix run, Back from 이지 카링 to the "zzz" entry rewrote
    that entry's URL to /?boss=easy-kaling.
 2. The dead entry: typing a full label fires onInput, which submits at once (the datalist-pick shortcut), and the
    Enter that follows submits again. A trace of history.pushState showed two pushes for one search
    ("push /?boss=hard-lotus&q=노말+카링 | push /?boss=normal-kaling&q=노말+카링"). The result depends on timing,
    which is why the critics saw 2->3->5.
 3. Found while fixing: history.replaceState("/?boss=<id>") changed the URL but left Next's router tree on the ?q=
    page. A second identical search ("카링 익스" twice, the P2-8 case) fetched the RSC, but Next reused the
    page as it was. A probe showed the same render token twice (f1f36422), and the field and URL kept "카링 익스".
Fix (BossSearch.tsx, page.tsx):
  - page.tsx passes rendered={crypto.randomUUID()}, which is new on every server render. The field effect is keyed
    on props only (rendered, value, bossId, missing), so it always matches the page on screen.
  - The field is rewritten only when a search was submitted or a popstate happened (ref `moved`). A refresh after
    adding a character renders the page too, and no longer touches what is being typed.
  - onSubmit skips a search that is already on its way (ref `sent`, cleared by any edit) and one whose text already
    names what is on screen (q === value). So the auto-submit + Enter pair pushes one entry.
  - The ?q= -> /?boss=<id> clean-up uses router.replace(..., { scroll: false }) instead of history.replaceState, so
    the router's tree matches the URL. It costs one extra RSC request per matched search.
  - Focus stays in the field. The field is still not remounted.
