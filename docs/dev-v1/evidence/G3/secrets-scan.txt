## Findings

No API key, token or private key of the project is in git history, the working tree, the build output or the client
bundle. Each scanner hit above, checked by hand:

1. `postgres://postgres:***@localhost:54329/maple_test` (G0 `pg-path.txt`, committed in ddcb272) and
   `postgres://postgres:***@localhost:54393/g3_1..8` (G3 `copy-p2/pg-path.txt`, not committed yet). The password is the
   same 10-character value in both, set by an agent for a throwaway embedded PostgreSQL 18.6 in /tmp that only
   listened on localhost for the `pg`-path test runs. Neither port has a listener now (`lsof -ti tcp:54329|54393
   -sTCP:LISTEN` is empty). Not a credential for anything that exists. Left as is: it is evidence, and the G0 copy is
   already in history. Optional: redact it in `copy-p2/pg-path.txt` before the G3 commit.
2. `TOGETHER_API_KEY: 'offl…'` twice in `.claude/skills/hallmark/scripts/fixtures/imagegen/imagegen.test.mjs`
   (committed in 74c11ae). A dummy value in the Hallmark skill's own test, which replaces fetch with a stub; not a key.
3. 39 matches in `pocs/.next` are Next.js's own constants (`PAGE_SEGMENT_KEY = "__PAGE__"`,
   `REQUEST_INSIGHTS_STORE_KEY = Symbol.for(...)`), skipped by name. 2 more in the working tree are the same names in
   the scanner's own comment.
